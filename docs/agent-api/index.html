CoverageFit Agent API · v1

Agent Capability API

CoverageFit exposes a narrow agent-facing API for approved service adapters. It can request a coverage review, schedule a callback, or request a licensed-human connection for an existing CoverageFit contact in California.

Boundary: This API does not bind insurance, cancel or replace a policy, return carrier pricing, accept payment information, expose raw CRM data, or authorize unrestricted marketing. CoverageFit remains the system of record and applies its own contact and consent checks.

API base: https://coveragefit.com/api/agent
OpenAPI: https://coveragefit.com/openapi.json
Capability manifest: https://coveragefit.com/api/agent/capabilities

Capabilities

Coverage review

insurance.coverage_review.request

Records a structured home, auto, or bundle review request for an existing CoverageFit contact.

Callback

insurance.callback.schedule

Requests a callback at an explicit date/time for a contact whose CoverageFit record permits calls.

Licensed-agent connection

insurance.agent.connect

Requests a human handoff for home, auto, bundle, or general insurance assistance.

Access requirements

  • Jurisdiction is currently limited to US-CA.
  • The request must reference an existing CoverageFit checkpoint/contact ID matching 408d_.... New-contact registration is not exposed in v1.
  • The calling service must be an approved, allowlisted adapter using CoverageFit's custom Mesh service authentication.
  • A fresh authenticated Mesh authority result with decision: ALLOW is required for each consequential invocation.
  • CoverageFit re-checks its own persisted contact and communication permissions before any live bounded action.

Authentication

POST /api/agent/invoke requires:

X-Mesh-Service-Auth: <base64url signed mesh-service-auth-v1 assertion>
Content-Type: application/json

The assertion is short-lived and bound to the calling service, audience, HTTP method, request path, body digest, timestamps, and a one-time nonce. It is replay-protected. This is not a static end-user API key. Credential provisioning for approved adapters is handled out of band.

Authentication is not user authority. A valid service assertion does not by itself grant permission to perform an insurance-related action. The invocation must also carry a fresh Mesh ALLOW evaluation, and CoverageFit consent remains authoritative.

Every invocation uses the same top-level envelope. Capability-specific fields belong only inside input. Unknown fields are rejected.

Execution modes

The current mode is published by GET /api/agent/capabilities.

  • PREPARE_ONLY: CoverageFit validates authentication, authority, contact state, consent, jurisdiction, idempotency, and input, then returns a structured PREPARED result without performing a live action. Initial accepted requests return HTTP 202.
  • LIVE_BOUNDED: The same validations apply, after which only the three documented bounded handlers may execute. Live enablement requires explicit CoverageFit configuration.

Idempotency and replay protection

Every request includes an opaque invocationId. Reusing the same ID with identical normalized data returns the prior result; reusing it with different data fails with HTTP 409. Service-auth nonces are one-time and replay-protected.
